## Контракт приёмника, как он есть в выкаченном файле

Прочитано по `routing/league-receiver.js` (2651 строка), не по дизайну:

- `GET /chat?gid=<32hex>&since=&gseq=` → `{ gid, seq, gseq, firstSeq, cold, more,
  messages[], gone[] }`; не член группы → **200** с `notMember: true` (не 401).
- `GET /chat?cur=<gid>:<seq>:<gseq>[,…]` → `{ updated, groups: { gid: <то же тело> },
  unknown: [] }`. `CUR_MAX = 16`, дубль gid → 400, страница 200 на весь ответ по кругу.
- `tail=1` действует ТОЛЬКО на группы с `since === 0` (`feedPick`), значит его можно
  посылать глобально в форме `cur=` — живые курсоры он не сбивает.
- Ни `gid`, ни `cur` в запросе (режим личности) → **400**, молчаливого дефолта нет.
- `att.url` в ленте — путь ПРИЁМНИКА: `/chat/att/<gid>/<seq>.<ext>` (в наследуемом
  режиме без gid). Хаб тело не переписывает (`leaguePass`), поэтому строить адрес хаба
  клиент обязан сам.
- Удаление в режиме личности требует `gid=`; чужое — автор или создатель группы, и даже
  создателю нужен `force=1`; `all=1` — только создатель.
- `GET /me` → `{ memberId, installId, nick, groups: [ { gid, title, mine, members } ] }`.
- `GET /group/<gid>` → `{ members: [ { memberId, nick, installId, rid, avatar, ver, sha,
  tzOffsetMin, lastAt } ] }` — единственное место, откуда наружу едут лица и `installId`.
- `/peers` в режиме личности — только белый список `PEER_PUBLIC` плюс `rid`.
- `POST /invite` → `{ id, code, blob: 'xgl1_…', expires, groups, maxUses }`, код в ответе
  ОДИН раз. `GET /invite`, `DELETE /invite/<id>`, `POST /join { invite | code }`.

## Найденное по ходу и починенное

### 🔴 `GET /league/me` на живом хабе отвечает 200 ЧУЖИМ телом

Замер на `:8200` (сборка без новых ручек): маршрут общего обзора лиги ловит запрос
**префиксом** (`url.startsWith('/__switch/api/league')`), поэтому `/league/me` возвращает
**200** и `{ me, peers, receiver }` — без `groups`. Первая версия `lgChatMe` верила коду
200: она решила бы «личность есть, групп ноль», погасила поле ввода и написала «ты ни в
одной группе» **поверх работающего чата**. Лечится проверкой ФОРМЫ: настоящий `/me` несёт
`ok: true`, `memberId` строкой и `groups` массивом. Закреплено проверкой с реальным телом
живого хаба.

Остальные новые ручки в тот же префикс проваливаются безвредно: `GET /invite` и
`GET /group/<gid>` отбиваются условиями `Array.isArray(j.invites)` / `j.members`, а POST'ы
до общего обзора не доходят (он только на GET) и получают 404 с `not_found`.

### 🪤 Коробка состояний стирала набранное приглашение

Поле «вставь приглашение» живёт внутри `#lg-gapbox`, а тот переписывался на каждую
перерисовку ленты, то есть на каждое пришедшее сообщение. Строку приглашения вставляют
руками — она бы исчезала на середине вставки вместе с фокусом. Теперь разметка
переписывается только при изменении (сравнение строк), значение хранить в состоянии не
пришлось: одноразовый код нигде не задерживается.

### 🪤 Ключи карт — чужие строки

`byRid`/`byId` состава группы и карта совпадений ников строятся из значений, приехавших с
чужих машин. Карты заведены через `Object.create(null)`, ключи состава сверяются с
`^[a-f0-9]{4,64}$`: ключ `__proto__` на обычном объекте меняет не запись, а прототип карты,
после чего поиск возвращает что попало. Закреплено проверкой на нике `__proto__`.

### Правило «cur= режем на 16» на стороне клиента

`CUR_MAX` приёмника — 16, и лишняя группа даёт **400 на весь запрос**, то есть ослепляет
все остальные. Клиент режет список сам и ставит активную группу первой, чтобы она не
выпала из среза.

## Перевёрнутое утверждение в чужую сторону

`tools/check-league-chat.js` держал проверку «на чтении есть CORS». Агент хаба снял
wildcard с `/chat` (дизайн § 3 требует снять его ВМЕСТЕ с этой проверкой), а файл проверок
мой — поэтому утверждение перевернул я: теперь закреплено, что на чтении чата
wildcard-CORS **нет**. Цена названа в комментарии: превью чата из черновика по `file://`
перестало работать; wildcard остался на общем обзоре лиги (витрина рейтинга).
