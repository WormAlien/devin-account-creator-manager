## Договорённости, из которых нельзя выйти

- Формы файлов заданы `tools/league-migrate.js` — читать РОВНО их, не менять:
  `members.json` (карта memberId), `groups.json` (карта gid), `invites.json` `{}`,
  `chat/<gid>.ndjson` / `.seq` / `.tombs.json` = `{v,gseq,cut,tombs:[{seq,at,gseq,why}]}`,
  `att|voice|files/<gid>/<номер>.<ext>`, `addr-salt` (64 hex).
- Личность — ТОЛЬКО из записи участника по хешу предъявленного токена. `installId`/ник из
  тела в решениях не участвуют (перезаписываются, как `recvAt`).
- Публичная выдача участников НЕ СОДЕРЖИТ `installId`, лица, `sha`, `tzOffsetMin` —
  отдельной функцией по белому списку, без ветвления «свой/чужой».
- Отзыв немедленный: `members.json` перечитывается по mtime на каждом запросе.
- Совместимость: старый общий секрет продолжает работать до перехода (живой обмен не ломать).

### 2. Приёмник переписан — сделано, 224/0 держатся

`routing/league-receiver.js` 1460 → 2637 строк. `node --check` проходит,
`node tools/check-league-receiver.js` = **224 прошло, 0 упало** (тесты ещё не дописаны —

**Ключевое решение — ДВА РЕЖИМА, и выбирает их РАСКЛАДКА ДАННЫХ, одним условием
«есть ли `members.json`»:**

- нет → `handlerLegacy`: ровно то, что было до 05.09. Общий секрет, личность из тела,
  плоский журнал. Это то, на что садится выкат ДО перевода данных — обмен в бою не ломается,
  и все 224 проверки продолжают проверять настоящее поведение, а не заглушку.
- есть → режим личности: токен → sha256 → запись, `installId`/ник/группы из записи,
  журнал на группу, `/peers` публичный и по белому списку.
- файл есть, но НЕ ЧИТАЕТСЯ → **503 на всё**, а не откат в наследуемый режим (иначе порча
  файла участников снова открывала бы всё общим ключом).
- Совместимость со старым ключом даётся бесплатно: переход кладёт в запись владельца
  `sha256(secret)`, поэтому тот же самый секрет продолжает работать — но уже как ЛИЧНЫЙ
  токен. Отдельной «лазейки для старого ключа» в коде нет: она и была бы обходом проверки.

Что сделано по коду:

1. `readState`/`writeState` — кеш по mtime+size, `none|ok|broken`; `authOf` (поиск по
   `sha256` токена, `hashEq` через `timingSafeEqual`, `status !== 'active'` → нет записи).
2. `chatPaths(gid)` — ОДНА функция на все пути; `gid === null` = плоская раскладка.
   `attFile(p, seq, ext)`.
3. Состояние журнала собрано в контекст на группу (`ctxOf`): свой кеш, свой `lastSeq`, свои
   надгробия. Кеш — до `CHAT_CACHE_SLOTS = 8` разобранных списков с вытеснением по
   давности чтения.
4. `handleSlice` + `sliceIdentity`: личность из записи, привязка `installId` первым срезом,
   409 на попытку сменить привязку, ник переезжает в запись.
5. `peerPublic` — белый список `rid,nick,recvAt,keys,tok,sp,tu,act,acc,tot,rebased(без
   sameAddr)`. Нет `installId`, `avatar`, `ver`, `sha`, `tzOffsetMin`.
6. `handleChatFeed`: `?gid=` (плоская форма ответа + `gid`), `?cur=gid:seq:gseq,…` (карта
   групп, `unknown[]`, страница 200 по кругу), `tail=1`, `before=`; без gid/cur → 400.
7. `handleChatDelete`: `mine=1`/`all=1` в пределах группы, `all=1` только создатель, чужое
   одно — создатель и только с `force=1`; `?installId=` в режиме личности не читается вообще.
8. `handleAtt` — `/chat/att/<gid>/<seq>.<ext>` с проверкой членства; плоский адрес в режиме
   личности отвечает 400 с объяснением.
9. Приглашения: `POST/GET /invite`, `DELETE /invite/<id>`, `POST /join`. Порядок проверок
   Headscale, обе ловушки закрыты, `usedBy` составным ключом, токен делает приёмник.
10. Группы: `POST /group`, `GET /group/<gid>` (лица и `installId` только членам),
    `POST /group/<gid>/member`, `DELETE /group/<gid>/member/<mid>[?purge=1]`,
    `DELETE /me`, `GET /me`.
11. `addrTag` солится файлом `addr-salt` (пока файла нет — секретом, иначе выкат обнулил бы
    живую серию просадок).
12. Ведра частоты на участника: `slice:<mid>`, `delete:<mid>`, `att:<mid>`, `invite:<mid>`,
    чат и голос по `memberId`. `MAX_INSTALLS` остался глобальным (он про диск).

### 6. Найденное по ходу и починенное

- 🪤 В `titleClean` в файл уехали ЖИВЫЕ управляющие байты (NUL, 0x1F, 0x7F) вместо escape-
  последовательностей ` ` и т.д. Регулярка работала правильно, но `grep` считал
  приёмник БИНАРНЫМ файлом («Binary file … matches»), и любой инструмент, читающий его
  текстом, спотыкался бы. Заменено на escape-и, проверено побайтово: управляющих байт в
  файле ноль. Первый выкат (md5 `4c7631c7…`) содержал этот NUL, второй (`17f95ebb…`) — нет.
