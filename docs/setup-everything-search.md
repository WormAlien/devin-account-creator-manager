# Гайд: быстрый поиск файлов для Claude Code через индекс Everything

> Это **инструкция по настройке** на новой машине, а не задача к исполнению. Раньше файл
> назывался `EVERYTHING-SEARCH-HANDOFF.md` — слово «хендофф» тут было лишним, отсюда и
> путаница с настоящим хендоффом (`HANDOFF-upstream-keepalive.md`, он один).

**Цель:** чтобы на новом компе Claude Code мог искать файлы по **всем дискам за миллисекунды** через NTFS-индекс Everything, вместо медленного `Glob`/`find` по дереву. Работает по всей машине, не только внутри проекта.

**Главное, что надо понять сразу:** никакого MCP-сервера, плагина, скилла или `es.exe` в этой схеме **нет**. Вся «интеграция» — это встроенный HTTP-сервер Everything и обычный `curl`. Со стороны Claude Code ставить не надо **ничего**. Настраивается только сам Everything + одна строчка-подсказка в `CLAUDE.md`.

---

## Как это работает у нас

1. **Everything 1.4.1.1032**, стоит в `C:\Program Files (x86)\Everything\Everything.exe` (32-битная сборка, несмотря на x64-систему — так встало, работает нормально).
2. Everything держит индекс всех NTFS-томов через USN-журнал → файл `%LOCALAPPDATA%\Everything\Everything.db` (у нас **168 МБ**, диски C, D, E, F, G, I).
3. У Everything включён **встроенный HTTP-сервер на порту 3553**.
4. Claude Code делает обычный `curl` на `http://127.0.0.1:3553/?search=...&json=1` и получает JSON со списком путей.

То есть цепочка: `Claude → curl → Everything HTTP :3553 → Everything.db`.

**У нас пароль не стоит** (пустые `http_server_username`/`http_server_password`). На новом компе логин и пароль будут свои — как это подключить, см. раздел «Логин и пароль» ниже.

## Настройка с нуля на новом компе

### Шаг 1. Установить Everything
С [voidtools.com](https://www.voidtools.com/). У нас 1.4.1.1032. Дать ему проиндексироваться (первый проход по всем дискам — минуты).

### Шаг 2. Разрешить HTTP-сервер на уровне установки
Файл **в папке установки**: `C:\Program Files (x86)\Everything\Everything.ini` — это маленький файл-переключатель, у нас он такой:

```ini
; Please make sure Everything is not running before modifying this file.
[Everything]
app_data=1
run_as_admin=0
allow_http_server=1
allow_etp_server=1
```

`allow_http_server=1` — **обязательно**. Это мастер-гейт: при `0` HTTP-сервер не только не стартует, но и **пропадает из настроек GUI**, так что галочку будет негде поставить. Этот ключ существует **только** в ini рядом с exe, в `%APPDATA%` его нет. `app_data=1` означает, что реальные настройки лежат в `%APPDATA%`.

### Шаг 3. Включить HTTP-сервер в основном ini
Файл настроек: `%APPDATA%\Everything\Everything.ini` (у нас `C:\Users\WormAlien\AppData\Roaming\Everything\Everything.ini`).

⚠️ **Everything должен быть закрыт при правке.** Это не перестраховка: по докам «any changes made to the Everything.ini while Everything is running are lost when Everything exits» — он перезапишет файл своим состоянием при выходе, и твои правки исчезнут. Сохранять как **UTF-8**.

Ключевые строки (наши значения):

```ini
http_server_enabled=1
http_server_port=3553
http_server_bindings=127.0.0.1
http_server_username=
http_server_password=
http_server_allow_file_download=1
ipc=1
run_in_background=1
```

Либо то же самое через GUI: **Tools → Options → HTTP Server → Enable HTTP server**, порт `3553`.

Про порт: по умолчанию Everything садится на **80**, и если он занят — падает с `bind failed 10048`. Мы поэтому и сидим на 3553; на новом компе оставь 3553, чтобы команды из этого хендоффа работали как есть.

### Шаг 4. Индексация томов
У нас индексируются все тома с живым мониторингом изменений:

```ini
ntfs_volume_paths="C:","D:","E:","F:","G:","I:"
ntfs_volume_includes=1,1,1,1,1,1
ntfs_volume_monitors=1,1,1,1,1,1
index_size=1
index_date_modified=1
index_folder_size=1
index_recent_changes=1
exclude_hidden_files_and_folders=0
exclude_system_files_and_folders=0
```

На новом компе список томов будет свой — GUI подхватит их сам, руками править не нужно. Важно только не выключать `monitors` (иначе индекс отстаёт от реальности) и не включать `exclude_hidden/system` (иначе не найдутся `.env`, `.claude` и прочие точечные папки — а они как раз нужны).

### Шаг 5. Автостарт
`run_in_background=1` + ярлык в автозагрузке (инсталлятор обычно ставит сам). Без работающего процесса Everything порт 3553 мёртв и поиск не работает.

## Логин и пароль

На новом компе у Everything будут свои креды. Ставятся так:

- **GUI:** Tools → Options → HTTP Server → поля Username / Password. Применяется **сразу, без рестарта Everything** (в отличие от правки ini).
- **ini:** `http_server_username=` / `http_server_password=` в `%APPDATA%\Everything\Everything.ini` (Everything закрыт!).

Пустое значение любого из них = аутентификации нет.

### ⚠️ Пароль в ini лежит открытым текстом

Документация voidtools нигде не обещает хеширование или обфускацию — `Everything.ini` это обычный текстовый файл (его даже можно открыть через `about:config` в самом Everything). Значит: **это файл с секретом**. Не коммитить, не кидать в чат, не копировать «на посмотреть» вместе с остальными конфигами. По конвенции проекта — то же правило, что и для `routing/*-keys.json`.

### Как передать креды в curl — не через командную строку

Очевидный вариант — `curl -u user:pass ...`. **Не делай так для постоянной работы.** Причина конкретная: команды, которые запускает Claude Code, целиком пишутся в историю и транскрипты (`~/.claude/history.jsonl` — у нас он уже 4.7 МБ логов команд, `~/.claude/projects/*/*.jsonl` тоже). Пароль в аргументе curl окажется в этих файлах в открытом виде навсегда, плюс будет видён в списке процессов.

Правильно — положить креды в `_netrc` и дать curl читать оттуда. На Windows файл называется **`_netrc`** (не `.netrc`), кладём в `%USERPROFILE%`:

`C:\Users\<USER>\_netrc`
```
machine 127.0.0.1
login ИМЯ
password ПАРОЛЬ
```

И дальше все запросы такие:

```bash
curl -s --max-time 6 --netrc-file "$HOME/_netrc" \
  "http://127.0.0.1:3553/?search=ЗАПРОС&json=1&path_column=1&count=40"
```

Путь указываем явно через `--netrc-file`, а не полагаемся на `-n`, потому что разные сборки curl под Windows по-разному ищут `_netrc` vs `~/.netrc`. Файл стоит закрыть от других юзеров (`icacls "%USERPROFILE%\_netrc" /inheritance:r /grant:r "%USERNAME%:R"`).

### Схема аутентификации — HTTP Basic

Доки voidtools схему не пишут, поэтому проверено по строкам в самом `Everything.exe` (1.4.1.1032): внутри есть `WWW-Authenticate`, `Basic realm` и `Authorization`, при этом **ни одного** маркера Digest (`Digest realm`, `qop=`, `nonce=`) — то есть сервер отдаёт `401` с Basic-челленджем и ждёт обычный `Authorization: Basic`.

Практический вывод: `--netrc-file` работает как есть, `--anyauth` **не нужен** (он только добавляет лишний пробный запрос). Если всё равно прилетает `401` — дело не в схеме, а в кредах: сверь логин/пароль в `_netrc` с полями Options → HTTP Server и проверь, что в `_netrc` стоит ровно тот хост, к которому обращаешься (`127.0.0.1`, а не `localhost` — netrc матчит по строке хоста).

Важное следствие Basic: пароль летит **base64, не шифрованием**, по открытому HTTP. В пределах `127.0.0.1` это неважно, но это ещё один довод не открывать порт в сеть (см. «Безопасность»).

## Как этим пользоваться

Базовый вызов (без пароля — как у нас; с паролем добавь `--netrc-file`, см. выше):

```bash
curl -s --max-time 6 "http://127.0.0.1:3553/?search=ЗАПРОС&json=1&path_column=1&count=40"
```

Ответ (реальный, проверенный):

```json
{
	"totalResults":2,
	"results":[
		{"type":"file","name":"keepalive-proxy.js","path":"C:\\Users\\WormAlien\\Desktop\\Autoreger_Clean\\routing"},
		{"type":"file","name":"routing__keepalive-proxy.js.bak","path":"C:\\Users\\WormAlien\\Desktop\\Autoreger_Clean\\_debug_garbage_2026-08-13"}
	]
}
```

`name` и `path` приходят раздельно — полный путь надо склеить самому.

### Грабли (проверены вживую, кроме отдельно помеченного)

- **`json=1` обязателен.** Без него сервер отдаёт HTML-страницу, и на ней `curl` у меня **завис наглухо** — не помог даже `--max-time`, подвесило сам bash-шелл на несколько минут (из-за этого часть проверок в этом хендоффе не доделана). Всегда добавляй `json=1`. Короткий алиас — `j=1`.
- **`path_column=1`** — иначе в ответе будет только `name` без папки, и результат бесполезен.
- **`count=N` ставь всегда — и вот почему.** В JSON-режиме дефолтный `count` = `4294967295`, то есть **все результаты без ограничения**. Забудешь `count` на широком запросе — получишь ответ на десятки тысяч строк и засрёшь себе контекст. (В HTML-режиме дефолт наоборот `32`.) Сколько всего нашлось — смотри в `totalResults`, оно не врёт независимо от `count`.
- **URL-энкодинг**: пробел → `%20`, `|` → `%7C`, `\` → `%5C`. Иначе bash порежет запрос на части.
- **`--max-time` всегда**, чтобы не повторить историю с зависшим шеллом.

### Синтаксис поиска (то, что реально гоняли)

| Запрос | Что делает |
|---|---|
| `ext:html\|jsx\|tsx\|vue` | по расширениям, `\|` = «или» |
| `folder:` / `file:` | только папки / только файлы |
| `C: size:>500mb` + `&sort=size&ascending=0` | крупные файлы на диске, по убыванию |
| `D:\ dashboard folder:` | папки с именем `dashboard` на диске D |
| `!node_modules` | исключить (префикс `!`) — почти всегда нужно |
| `path:routing` | искать по полному пути, а не только по имени |
| `dm:today`, `dm:lastweek` | по дате изменения |

GET-параметры: `sort=size|name|date_modified`, `ascending=0|1`, `offset=N`, `count=N`, `case=1`, `regex=1`, `wholeword=1`. Доп. поля в JSON включаются по одному: `path_column=1`, `size_column=1`, `date_modified_column=1`, `date_created_column=1`, `attributes_column=1`.

## ⚠️ Безопасность

У нас сейчас сервер слушает **`0.0.0.0:3553` и `[::]:3553` без пароля** (проверено через `netstat`), а `http_server_allow_file_download=1`. Формулировка самих voidtools: «every file and folder indexed by Everything can be searched and downloaded via the web server». То есть любой в той же локальной сети листает все диски и качает файлы. Дома за роутером терпимо, на ноуте в кафе — нет.

На новом компе пароль решает главную проблему, но поставь **и** ограничение по интерфейсу — для нашей задачи (curl с той же машины) внешний доступ не нужен вообще:

- `http_server_bindings=127.0.0.1` — слушать только локально. **Рекомендуемый вариант**, стоит одну строку.
- Пароль (см. выше) — второй слой, если доступ по сети всё-таки нужен.
- `http_server_allow_file_download=0` — если нужен только поиск имён, без скачивания. Для наших целей скачивание не нужно.

## Как заставить Claude этим реально пользоваться

**Это самый важный пункт, и у нас он сейчас не сделан.** Настроенный Everything сам по себе ничего не даёт: Claude про порт 3553 не знает и по умолчанию полезет искать через `Glob`/`find`. Никакого правила в `CLAUDE.md` у нас нет — я пользовался этим только потому, что нашёл порт в конфиге по ходу дела.

Чтобы работало из любой папки, добавь блок в **глобальный** `~/.claude/CLAUDE.md`:

```markdown
# Поиск файлов по всей машине — Everything

На машине работает Everything с HTTP-сервером на :3553, индексирует все диски.
Когда надо найти файл **за пределами текущего проекта** (или быстро просканировать
весь диск) — не используй Glob/find по дискам, спрашивай Everything:

    curl -s --max-time 6 --netrc-file "$HOME/_netrc" \
      "http://127.0.0.1:3553/?search=ЗАПРОС&json=1&path_column=1&count=40"

Сервер под логином/паролем (HTTP Basic) — креды лежат в `%USERPROFILE%\_netrc`,
брать только оттуда через `--netrc-file`. НИКОГДА не подставляй пароль в
`-u user:pass`: командная строка попадает в history.jsonl и транскрипты в открытом
виде. Если прилетел 401 — это не схема, а креды: сверь `_netrc` с Options → HTTP
Server и убедись, что в `_netrc` хост записан как `127.0.0.1`.

Правила: `json=1` обязателен (без него curl вешается на HTML-странице),
`path_column=1` обязателен (иначе нет папки), `count` ставь ВСЕГДА — в JSON-режиме
дефолт без ограничения, широкий запрос вернёт десятки тысяч строк. Общее число
смотри в `totalResults`. Энкодинг: пробел `%20`, `|` `%7C`, `\` `%5C`.
Синтаксис: `ext:js|ts`, `folder:`, `file:`, `!node_modules`, `path:`,
`size:>500mb`, `dm:today`. Сортировка: `&sort=size&ascending=0`.

Внутри текущего проекта по-прежнему используй Glob/Grep — они дают контекст кода,
Everything знает только имена и пути.
```

Последний абзац важен: Everything ищет **только по именам и путям**, содержимое файлов он не индексирует. Grep он не заменяет — заменяет `find`.

## Чек-лист приёмки на новом компе

1. `netstat -ano | grep 3553` → есть строка `LISTENING`.
2. `curl -s --max-time 6 --netrc-file "$HOME/_netrc" "http://127.0.0.1:3553/?search=Everything.ini&json=1&path_column=1&count=3"` → приходит JSON с путями. Если `401` → креды в `_netrc` не совпали с Options → HTTP Server, либо хост в `_netrc` записан не как `127.0.0.1`.
3. Проверить, что **без** кредов запрос отбивается (иначе пароль не применился): тот же curl без `--netrc-file` должен дать 401, а не результаты.
4. Поискать заведомо существующий файл проекта → находится с правильным путём.
5. `http_server_bindings=127.0.0.1` выставлен, `_netrc` закрыт от других юзеров.
6. Блок из предыдущей секции добавлен в `~/.claude/CLAUDE.md`, Claude Code перезапущен.
7. Спросить у Claude «найди на диске файл X» → он должен дёрнуть curl на 3553, а не пойти в Glob.
