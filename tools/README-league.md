# Лига: приёмник и чат на швейцарской ноде

Рунбук. Только команды и признаки успеха; как это устроено — в комментариях
самих файлов и в вике ([[Рейтинг расхода в ABUSE HUB — аудит учёта и план]]).

## Как подключить участника

🪤 **Этот раздел про сегодняшнюю модель: один общий ключ на всех.** Она спроектирована
на замену — личный токен у каждого, приглашение одной строкой `xgl1_…`, группы и три
уровня отзыва. В коде приёмника этого ещё нет, поэтому ниже всё верно, но конечно:
когда личность появится, ритуал из трёх значений умрёт, а раздел переписывается целиком.
Разбор — вики: «Лига — друзья, группы и приглашения (дизайн)».

От владельца нужно три значения: `url`, `key`, `pin`. Доступа к ноде участнику не
нужно, рестарт хаба — тоже (кроме шага 1).

Владельцу — откуда их взять: `url` и `pin` уже лежат в его собственном
`routing/league-config.json`, секрет — там же и в `/opt/league/data/secret` на ноде.
Отпечаток можно пересчитать с ноды: `openssl x509 -in /opt/league/league-cert.pem
-noout -fingerprint -sha256`. Передавать — как написано ниже, в личке.

### 1. Убедиться, что в хабе есть код лиги

Открыть `http://127.0.0.1:8200/__switch/api/league`.

- JSON с полями `me` / `peers` / `receiver` — код есть, шаг 2.
- `404` с `not_found: true` — процесс поднят на сборке без лиги. В теле ответа хаб сам
  пишет, когда правлен код и когда поднят процесс (`stale_process`), и чем перезапускать.
  `git pull`, потом `npm run restart`. **Это единственное место, где рестарт нужен**:
  файл на диске новый, а в памяти живёт прежний код — та же ловушка, что с `--no-restart`
  на выкате.

### 2. Положить настройки

Файл — `routing/league-config.json`, рядом с `transparent-proxy.js` (путь считается от
самого хаба: `path.join(__dirname, 'league-config.json')`, функция `leagueConfig`).
В git не попадает, `.gitignore` его уже знает. Значения — заглушки, реальные берутся
у владельца:

```json
{
  "enabled": true,
  "url": "https://<ip приёмника>:8420",
  "ip": "<тот же ip; нужен, только если в url имя, а не цифры>",
  "pin": "<sha256-отпечаток от WormAlien>",
  "key": "<ключ от WormAlien>",
  "everyMin": 10
}
```

То же самое, но с проверкой и без ручного JSON:

```
node tools/league-join.js --url=https://<ip>:8420 --pin=<sha256> --key-file=key.txt
node tools/league-join.js --check-only      # ничего не писать, проверить лежащее
node tools/league-join.js --dry-run         # показать, что записалось бы
```

Существующий конфиг помощник не затирает — только с `--force`. Секрет он не печатает
(лишь длину) и умеет брать его из файла или `LEAGUE_KEY`, чтобы тот не попал в историю
оболочки.

Проверка шага: `node tools/league-join.js --check-only` печатает
`итог: приёмник отвечает, секрет принят` и выходит кодом 0.

### 3. Дождаться обмена — конфиг перечитывается на ходу

Рестарт не нужен: `leagueConfig()` читает файл при каждом обращении, а тик
(`leagueTick`) сам себя перепланирует и заново берёт `everyMin`. Первый тик — через
минуту после старта хаба, дальше каждые `everyMin` минут (меньше 2 не бывает,
пропущенное или битое поле = 10).

Не ждать: `curl -X POST http://127.0.0.1:8200/__switch/api/league/sync`. Кнопки в
дашборде для этого нет. Второй срез в ту же минуту приёмник отвергает — `429 один срез
в минуту`, это не поломка.

Проверка шага — `receiver` в ответе `/__switch/api/league`:

| что видно | что это значит |
|---|---|
| `configured: false` + `note: приёмник не настроен…` | файла нет, либо в нём нет `url`/`key`, либо `enabled: false` |
| `configured: true`, `last.at: null`, `last.ok: null` | настроено, но тика ещё не было — ждать до `everyMin` минут |
| `last.ok: true`, `last.peers: N` | обмен прошёл, соседей видно N (ноль — значит другие пока не подключились) |
| `last.ok: false`, `last.error: "…"` | обмен падает, причина тут же текстом |

Второй независимый признак: файл `routing/league-peers.json` появляется только после
первого удачного обмена. Ошибки обмена уходят и в лог хаба строкой
`league sync (<url>): …` — вкладка «Логи».

⚠️ `configured: false` не различает «файла нет» и `enabled: false` — текст подсказки
говорит про отсутствующий файл в обоих случаях. Если выключал участие сам, помни об этом.

### 4. Ник и лицо

Ник лежит в `routing/hub-identity.json` рядом с `installId`. Если поля нет, хаб берёт
`git config user.name`, а если и его нет — `hub-<4 hex>`. **Если в git-конфиге настоящее
имя, оно и уедет соседям** — поменяй до первого обмена.

- Сменить: вкладка «Лига», карандаш у ника (это `POST /__switch/api/league/nick`).
  Правила: 2–20 символов, пробелы → `_`, остаётся только буквы/цифры/`_.-`.
- `installId` при переименовании не меняется — второй строки в рейтинге не будет.
- Аватарка: `POST /__switch/api/league/avatar` из вкладки, webp до 20 КБ. Отдельной
  ручки у приёмника для неё нет: лицо разносит сам обмен, внутри среза.

### 5. Выключить участие

`"enabled": false` в `routing/league-config.json` (или убрать файл). Действует с
следующего тика, рестарт не нужен, наружу перестаёт уходить всё.

Что остаётся после выключения:

- твой последний срез лежит на ноде и ещё **36 часов** отдаётся соседям (`STALE_MS`),
  потом выпадает из `/peers`; сам файл на диске ноды остаётся до ручного удаления;
- `routing/league-peers.json` остаётся у тебя, и вкладка продолжает показывать
  последний снимок соседей — это кэш, а не живые данные;
- чат замолкает: чтение отдаёт пустой список с пометкой, отправка — `503`.

### Что уедет соседям, а что нет

Приёмник не хранит присланный срез как есть: он собирает его **заново по белому списку**
(`sliceClean` в `routing/league-receiver.js`). Соседям доходит ровно это:

| поле | что это |
|---|---|
| `installId`, `nick` | id установки (16 hex) и ник |
| `recvAt` | время приёма — ставит приёмник, клиентскому времени он не верит |
| `ver`, `sha` | версия хаба и короткий sha HEAD твоего чекаута |
| `avatar` | аватарка, если поставил (webp ≤ 20 КБ) |
| `tzOffsetMin` | смещение часового пояса |
| `keys` | подписи бакетов (даты и часы) по четырём окнам: сутки/7/30/всё время |
| `tok`, `sp`, `tu`, `act`, `acc` | ряды по тем же окнам: токены, сожжено $, налито $, промпты, накопленные аккаунты |
| `tot` | 25 чисел-итогов: `tokD/W/M/A`, `spD/W/M/A`, `tuD/W/M/A`, `bal`, `spentAll`, `promptsAll`, `ppd`, `streak`, `bought`, `reg`, `keys` (сколько ключей на шлюзах, число), `accDated`, `accD/W/M/A` |

Не доходит:

- **`src`** — диагностика сшивки: `perPool` (сколько ключей на каждом шлюзе по именам),
  `boughtCreds`, размеры журналов, суммы отсеянного дедупом. Хаб её в теле POST
  **отправляет**, но приёмник не кладёт на диск и соседям не отдаёт. То есть до соседей
  не доедет, а по сети до ноды — доедет; владелец ноды технически может её видеть.
- **`stamp`** — время отправителя, выбрасывается.
- Ключей, токенов, почт, логинов, паролей, текста промптов, ссылок и путей в срезе нет
  вообще — только счётчики. Регресс на это стоит в `tools/check-league.js`.

Отдельно: `/health` у приёмника отвечает **без ключа** и печатает, сколько установок
сдаёт срезы. Больше он без ключа не отдаёт ничего.

### Секрет один на всех — что это значит

Ключ общий, отдельных на человека нет. Прямо и без прикрас:
- любой участник может вычистить общий чат целиком (`DELETE /chat?all=1`) и удалить
  чужое сообщение (`force=1`);
- любой участник может отправить срез под чужим `installId`: приёмник проверяет форму и
  правдоподобность роста, а не личность;
- любой участник читает срезы всех остальных — на этом лига и построена.

Совпадение `installId` — **ограда от промаха, а не право доступа**: своё удаляется без
оговорок, чужое требует явного `force=1`. Защитой это не является и притворяться иначе
нечестно.

Ещё одна связка, невидимая до первой смены ключа: **`secret` служит солью хеша адреса**
(`slice-owners.json`, `slice-drops.json`). Сменить ключ — значит превратить оба файла в
мусор: живая серия просадок обнуляется, а признак «тот же адрес» начинает врать.
Пересолить нечем, там только хеши. Поэтому переход на группы заводит **отдельный**
`addr-salt` и оба файла сносит явным шагом (копии остаются в снимке).

### Как передавать секрет

Лично: личка в мессенджере, которым вы и так пользуетесь, или голосом. **Не в git, не в
вику, не в общий чат лиги.** Секрет живёт ровно в двух местах: `/opt/league/data/secret`
на ноде и `routing/league-config.json` у каждого (файл в `.gitignore`).

- Промежуточный `key.txt` для `--key-file` удалить сразу после подключения.
- `--key=` в командной строке оставляет секрет в истории оболочки — помощник об этом
  предупреждает в выводе.
- Резервных копий конфига помощник не делает намеренно: `league-config.json.bak` в
  `.gitignore` не значится и однажды уехал бы в коммит.

### Если не работает

**Сначала контроль, потом выводы.** Путь к приёмнику идёт через туннель, чей выход — та
же швейцарская нода: внешний IP машины владельца замерен как `185.114.117.145`, `loc=CH`.
Поэтому падение туннеля выглядит как смерть приёмника: `EACCES` на исходящее, SSH не
идёт, `/health` таймаутит — и всё это при живой ноде. Дёрни любой посторонний HTTPS:

```
curl -sS -o /dev/null -w '%{http_code} %{time_total}\n' https://cloudflare.com/cdn-cgi/trace
```

Лёг и он — виноват туннель или сеть, приёмник тут не при чём. `league-join.js` делает
этот запрос сам и печатает его первым. Для сравнения, живое состояние 05.09: контроль
`200` за 746 мс, `/health` шестью подряд рукопожатиями — 718 / 1380 / 646 / 1566 / 681 /
618 мс, ни одного таймаута.

**SNI отправлять нельзя.** Запрет остался, а вот режим отказа сменился, и узнать надо оба:
раньше запрос с `servername` висел и рвался таймаутом ~18 с, теперь падает быстрым
`ECONNRESET` за ~2.1 с. Причина одна: туннель смотрит SNI в ClientHello и уводит наши
домены «напрямую», а напрямую нода недоступна. Соединяемся по IP, `servername: undefined`,
подлинность — отпечатком. Node сам не ставит IP в SNI, так что адрес-цифры и есть пустой SNI.

**«Порт открыт» не доказывает ничего.** Проба порта через туннель успешна ВСЕГДА: локальный
TUN сам отвечает на рукопожатие. Доказано отрицательным контролем — заведомо закрытый
`12345` «подключился» за 8 мс так же, как рабочий `8420`. `ping` бесполезен по той же
причине. Единственное доказательство — **HTTP-код от приёмника**: `/health` вернул `200`
и в теле `{"ok":true,…}`.

**Пиннинг требует свежего рукопожатия.** На возобновлённой TLS-сессии сервер сертификат
не присылает, `getPeerCertificate()` отдаёт пустой объект, и сверять нечего: первый обмен
проходит, второй падает с «отпечаток не совпал», причём отпечаток в ошибке пустой. Лечится
агентом без переиспользования сессий, и это проверено, а не предположено: со свежим
`tls.connect` при `keepAlive: false, maxCachedSessions: 0` сертификат непустой на всех 12
рукопожатиях замера.

Кто копирует код себе — копируйте целиком, вместе с местом проверки:

```js
const agent = new https.Agent({ keepAlive: false, maxCachedSessions: 0 });
// … opts.agent = agent; opts.rejectUnauthorized = false; opts.servername = undefined;
req.on('socket', s => s.on('secureConnect', () => {
  const got = (s.getPeerCertificate().fingerprint256 || '')
    .replace(/[^A-Fa-f0-9]/g, '').toUpperCase();
  if (got !== PIN) req.destroy(new Error('отпечаток не совпал'));
}));
```

Отпечаток сверяется в `secureConnect`, то есть **до отправки первого байта**. Проверка
после записи тела бессмысленна: секрет к тому моменту уже у чужого сервера.

#### Коды, которые говорят конкретное

- `401` — приёмник не принял секрет: не тот, обрезан при копировании или с лишним пробелом.
  `/health` при этом отвечает `200`, потому что ключа не требует.
- `409 срез не сходится с прошлым` — счётчики просели больше чем на 10 % или выросли выше
  часового потолка. Это антинакрутка. Если счётчики упали законно (переставил хаб, вычистил
  журналы), сам ты это не исправишь: файл прежнего среза лежит на ноде и не устаревает —
  нужен владелец, удалить `/opt/league/data/slices/<installId>.json`.
- `429` — либо второй срез в ту же минуту, либо больше 20 сообщений чата в минуту.

⚠️ **Непроверенное: доступность приёмника из интернета МИМО туннеля не подтверждена.** Всё,
что измерено, шло через туннель с выходом на той же швейцарской ноде, и с рабочей машины
владельца проверить путь «без туннеля» нельзя. У участника с другим VPN или без него путь
может отличаться. Поэтому здесь не написано «работает из любой сети»: проверяй у себя, и
проверяй **HTTP-ответом `/health`** — не пингом и не пробой порта.

## Вложения: три каталога, три срока

Каталог решает срок хранения, а не вид файла: `tmpfiles` умеет срок только на путь
целиком, поэтому каталогов три.

| каталог | что там | срок | по какому времени |
|---|---|---|---|
| `att/` | картинки (webp, проверен сигнатурой) | 30 суток | доступа |
| `voice/` | голосовые: `webm`, `ogg`, `m4a`, `mp3`, `wav` | **7 суток** | модификации (`m:`) |
| `files/` | всё остальное: markdown, конфиги, pdf | 30 суток | модификации (`m:`) |

На диске файл всегда лежит **под номером сообщения** (`844.pdf`), а исходное имя —
поле записи журнала. Это не стиль: имя приходит от человека, и в пути оно означало бы
обход каталога прямым текстом.

Следствие, которое надо знать до того, как о нём спросят: **сообщение в журнале может
пережить своё вложение.** Журнал держит последние 1000 сообщений, а вложение уходит по
сроку — тогда отдача даёт `404`, и это норма, а не поломка. У голосовых так вчетверо
чаще (7 суток против 30).

Тип решают **байты** (сигнатура), а не заявленный `mime` и не расширение в имени.
Не опознали — `415`.

## Надгробия: почему удалённое исчезает у соседей

Протокол чтения умеет только «добавилось», поэтому снятое сообщение висело бы у всех до
перезагрузки страницы. Теперь каждое решение человека убрать сообщение пишет надгробие в
`chat-gone.json`:

```json
{ "v": 2, "gseq": 42, "cut": 7,
  "tombs": [ { "seq": 1791, "at": "2026-09-05T18:00:00.000Z", "gseq": 42, "why": "one" } ] }
```

- `gseq` — **свой монотонный курсор**, не время и не номер сообщения. По времени
  фильтровать нельзя (ход часов назад спрятал бы надгробие навсегда), по номеру тем
  более: удалённый номер по определению ниже курсора клиента.
- `cut` — самый большой `gseq`, который приёмник **уже забыл** (истёк по сроку или
  вытеснен потолком). Клиенту ниже `cut` отвечаем `cold` — «не знаю, перечитай хвост».
  Пустой список вместо этого читался бы как «ничего не пропало».
- Обрезка журнала по лимиту надгробий **не ставит**: она снимает 1000 сообщений
  непрерывным низом и описывается одним числом `firstSeq` в ответе.

🔴 **`gseq` и `cut` нельзя перенумеровывать ни при каких переносах.** Серверный курсор
ниже запомненного клиентами = «перечитай хвост» у всех сразу, то есть общий сбой в тот
момент, когда все считают операцию успешной. Скрипт перехода переносит их как есть, и на
это стоит проверка с мутацией.

## Выкатить

```
node tools/deploy-league-receiver.js --dry-run     # план, соединения не будет
node tools/deploy-league-receiver.js              # сделать
```

Из git-bash — с `MSYS_NO_PATHCONV=1`, иначе bash перепишет `/opt/...` в
`D:/git/opt/...`. Скрипт это ловит и останавливается, но лучше сразу.

Признаки успеха, по порядку: `md5 на ноде совпал с локальным`, бэкап лёг с тем же
md5, что был у прежнего файла, `league-receiver активен`, `/health отвечает`.
Любой другой ответ — скрипт встаёт и говорит, на каком шаге.

Полезные ключи: `--skip-conf` (не трогать рецепт), `--no-restart` (только
скопировать), `--patch-conf` (поправить пути в рецепте под фактический DATA),
`--migrate` (перевести данные, см. ниже), `--force-layout` (подавить отказ по
несовпадению кода и раскладки данных), `--host/--port/--user/--key/--remote/--data/--unit`
(всё переопределяемо), `--alias=ch` (ходить через алиас из `~/.ssh/config`).
Полный список — `--help`.

Что выкат проверяет сам, кроме md5:

- **все три правила рецепта чистки**, каждое со своим каталогом. Разъехался путь у
  звука — остановка: иначе чистка «работает», удаляя ноль файлов;
- **раскладку данных на ноде против выкатываемого кода** (проба до первого изменения).
  Приёмник, не знающий про группы, на групповые данные — **отказ**, а не предупреждение.
  Почему: журнала на прежнем месте нет → счётчик восстанавливается с нуля → новые
  сообщения получают номера 1, 2, 3 → это ниже курсоров всех клиентов, а выдача отдаёт
  только «номер больше курсора». Итог — пустой чат у всех и ни одной ошибки нигде.
  Признак «знает про группы» — упоминание `members.json` / `groups.json` / `tombs.json` в
  файле приёмника; врёт — `--force-layout`, но тогда причина названа заранее.

⚠️ `--no-restart` означает, что **в памяти живёт прежний код**: файл новый, ручек
чата нет. Это ровно та ловушка, на которой в этом проекте уже стояли не раз.

## Перевести данные на групповую раскладку

Отдельный флаг намеренно: выкат кода обратим бэкапом и рестартом, перевод данных — только
снимком.

```
MSYS_NO_PATHCONV=1 node tools/deploy-league-receiver.js --dry-run --migrate   # план
MSYS_NO_PATHCONV=1 node tools/deploy-league-receiver.js --migrate             # сделать
```

Порядок внутри шага: сухой прогон перехода на ноде (только читает) → `systemctl stop`
(пока сервис жив, он пишет в старый журнал) → снимок → перенос → обычный рестарт и
приёмка `/health`. Каталог данных берётся **из живого юнита**, не из параметра.

Порядок между шагами — сначала код, потом данные, и **промежуточное состояние штатное**:
групповой приёмник обязан подниматься и на прежней раскладке, поэтому после выката кода
чат продолжает работать как раньше. Выкат в этот момент напоминает предупреждением, что
перевод ещё не сделан, — это не авария. Обратный порядок (данные переведены, код плоский)
выкат делать откажется: он и есть та молчаливая поломка из «Грабель».

Что делает переход (`tools/league-migrate.js`, ноль зависимостей, идемпотентен):

| было | стало |
|---|---|
| `chat.ndjson` | `chat/<gid>.ndjson` — **без перенумерации**, номер это имя файла вложения |
| `chat-seq` | `chat/<gid>.seq`, значение сохраняется |
| `chat-gone.json` | `chat/<gid>.tombs.json`, `gseq` и `cut` как есть; источник остаётся на диске |
| `att/`, `voice/`, `files/` | `att/<gid>/`, `voice/<gid>/`, `files/<gid>/`, имена файлов те же |
| — | `members.json`, `groups.json`, `invites.json`, `addr-salt` |
| `slice-owners.json`, `slice-drops.json` | **снесены**: соль сменилась, в них только хеши |
| `slices/*.json` | не тронуты вовсе |

`installId` берётся из `slices/` и **никогда не генерируется** — на нём висит весь
накопленный рейтинг. Срезов не один или ни одного — переход отказывается, а не угадывает
(`--install-id=`). Общий `secret` становится личным токеном владельца: на диск идёт только
его `sha256`, сам секрет не печатается и на машине владельца не правится ни один файл.

Признак успеха — последняя строка `MIGRATE-OK gid=… messages=… att=… tombs=… gseq=…`.
`gid` печатается **один раз**: это он уезжает в конфиг участников.

Обратный ход:

```
MSYS_NO_PATHCONV=1 node tools/deploy-league-receiver.js --rollback --rollback-data
```

Снимок откат **не удаляет** — он и есть доказательство прежнего состояния. Лежит двумя
частями: `chat-<штамп>.bak.ndjson` (тем же именем, что пишет `chatBackup`, поэтому его
накрывает удержание пяти снимков) и `migrate-<штамп>/` с копиями мелких файлов состояния и
манифестом. Упало посередине — повторный запуск **доделывает начатое** тем же `gid`.

## Откатить

```
node tools/deploy-league-receiver.js --list-backups
node tools/deploy-league-receiver.js --rollback
node tools/deploy-league-receiver.js --rollback --backup=league-receiver.js.20260905-101500Z.bak
```

Перед возвратом скрипт прогоняет `node --check` на бэкапе и снимает копию того,
что лежит сейчас (`*.pre-rollback.bak`) — откат тоже обратим. `--rollback` возвращает
**только код**; раскладку данных возвращает `--rollback-data` (см. раздел выше).

## Проверить

```
node tools/check-league-chat-e2e.js            # против живого приёмника
node tools/check-league-migrate.js             # переход данных + вердикты выката
node tools/check-league-migrate.js --mutants   # и таблица мутаций
```

Регресс перехода собирает в песочнице копию настоящей раскладки (журнал с вложениями
трёх видов, срез, счётчик, надгробия v2, `slice-owners`/`drops`, старые снимки) и гоняет по
ней настоящий скрипт: перенос без перенумерации, вложения по каталогам с побайтовой
сверкой, `gseq`/`cut` без перенумерации, идемпотентность по отпечатку всего каталога,
обратный ход, доделывание после обрыва, отказы. Ноду и сеть не трогает.
`--mutants` портит проверяемый код по одной правке и требует, чтобы тест краснел на каждой.

Сквозная (`check-league-chat-e2e.js`) ходит на живой приёмник так же, как хаб: по IP, без
SNI, с проверкой отпечатка. Проходит весь путь — отправка, чтение по `since=`, вложение
webp, сверка байтов, `429` после лимита, `401` на чужом ключе.

- Ручек чата на ноде нет (старый код) → скажет словами и выйдет кодом **0**.
- Прогон **оставляет в чате свои сообщения** (~20 из-за проверки лимита) и в конце
  печатает, что оставил. Тихий вариант — `--no-flood` (2 сообщения).
- Своя квота чата не тратится: по умолчанию скрипт ходит под отдельной тестовой
  установкой. Под своей — `--as-me`.
- Убрать за собой можно: `DELETE /chat?installId=<тестовый>` сносит все сообщения этой
  установки, `DELETE /chat/<seq>` — одно (чужое только с `force=1`). Перед массовым
  удалением приёмник сам делает снимок журнала. Не убрал — уйдут сами, когда журнал
  обрежется до последних 1000.
- 🪤 Личность участника ещё не реализована, поэтому тестовая установка ходит **под общим
  ключом**. Когда токены станут личными, этой проверке понадобится свой участник, иначе
  она начнёт падать на `401`, и причина будет выглядеть как поломка приёмника.

Прогнать путь записи, не трогая ноду: поднять приёмник локально
(`node routing/league-receiver.js 8433 <пустой каталог>`), взять секрет из
`<каталог>/secret` и позвать проверку с переопределением адреса:
`node tools/check-league-chat-e2e.js --url=http://127.0.0.1:8433 --key=<секрет>`.

## Где секрет

`/opt/league/data/secret` на ноде (права 0600, печатается ОДИН раз при создании) и
его копия в `routing/league-config.json` вместе с отпечатком сертификата (`pin`).
В логи, в чат и в отчёты не попадает — скрипты печатают только длину.
Разъехались — `401` на всех ручках, кроме `/health`.

## Если приёмник не отвечает

По порядку, на ноде:

```
systemctl status league-receiver                 # активен ли
journalctl -u league-receiver -n 50 --no-pager   # что сказал перед смертью
ss -ltnp | grep 8420                             # слушает ли порт
curl -ksS https://127.0.0.1:8420/health          # отвечает ли себе самому
```

Отвечает себе, но не отвечает нам — путь, а не сервис: из РФ нода видна только
через VPN (`happ-tun`), а входной фильтрации на CH нет, ufw выключен.
Отвечает нам, но проверка ругается на отпечаток — сменился сертификат, надо
обновить `pin` в `routing/league-config.json`.

## Грабли

- **Путь в рецепте чистки и каталог данных — разные вещи, и правил ТРИ.** Рецепт чистит
  `<путь>/att`, `<путь>/voice`, `<путь>/files`, а приёмник кладёт вложения в `<DATA>/…`.
  Разъехался хоть один — чистка будет исправно работать, не удаляя ничего. Скрипт выката
  берёт `DATA` из живого юнита, сверяет **все три** правила и на расхождении
  **останавливается**; нет правила на каталог — тоже останавливается (каталог без правила
  растёт вечно). Осознанно обойти — `--patch-conf` (правит только копию, которая едет на
  ноду) или `--skip-conf` (выкатить без чистки).
  🪤 До 05.09 сверялось **первое совпадение** — то есть `voice` и `files` не проверялись
  вообще. Это тот же класс, из-за которого однажды месяцами чистили пустой каталог.
- **После перехода на группы файлы лежат на уровень глубже правила** (`att/<gid>/838.webp`),
  и совпадение путей больше не доказывает, что чистка работает. Подтвердить сразу нечем:
  `systemd-tmpfiles --clean --dry-run` перечисляет только то, что **уже** состарилось, а
  сразу после перехода стареть нечему. Поэтому выкат честно говорит «приёмка отложена» и
  печатает, что проверить потом: в выводе `--clean --dry-run` обязан быть путь **внутри**
  подкаталога группы; нет — добавить в рецепт правила с шаблоном `att/*`, `voice/*`, `files/*`.
- **Плоский приёмник на групповые данные ломает чат МОЛЧА.** Журнала на прежнем месте нет
  → счётчик восстанавливается с нуля → новые сообщения получают номера 1, 2, 3 → это ниже
  курсоров всех клиентов, а выдача отдаёт только «номер больше курсора». Итог: пустой чат
  у всех, ни одной ошибки. Выкат отказывается это делать; лечится либо групповым
  приёмником, либо `--rollback --rollback-data`.
- **`systemd-tmpfiles-clean.timer` в состоянии `static` — это норма**, у него нет
  `[Install]`, его тянет `timers.target`. Решает `is-active`, а не `is-enabled`.
  Не тикает — включает владелец: `systemctl enable --now systemd-tmpfiles-clean.timer`.
- **Пину нужно свежее рукопожатие.** На возобновлённой TLS-сессии сервер не
  присылает сертификат заново, и сверять нечего: отсюда агент без keep-alive и
  новое соединение на каждый запрос. Не «оптимизировать».
- **Окно антифлуда живёт в памяти.** После рестарта приёмника лимит обнуляется —
  это не «лимит не работает», а осознанное решение не писать счётчик флуда в файл.
- **CRLF в `routing/league-receiver.js` безразличен для `node file.js`**, но убил бы
  прямой запуск по shebang. Скрипт выката про CRLF предупреждает, md5 сверяется
  побайтово, так что перевод строк на выкат не влияет.
